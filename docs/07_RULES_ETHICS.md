# 07: Rules, ethics and their software consequences

This is orientation for the engineering work, not legal advice. Each rule below turns into a
concrete software requirement.

| Area | What applies | Software requirement |
| --- | --- | --- |
| Laws of the Game, Law 4 (IFAB) | Team officials may use small handheld devices for player welfare/safety or tactics/coaching. Wearables must not be dangerous and must meet the FIFA Quality Programme for EPTS, approved by the competition. If the organiser supplies tracking, it is responsible for reliability of data sent to the bench. | App targets tablet/phone/watch only. Source of every data stream recorded in logs (`source` field). No player-worn output device. |
| Competition rules | Leagues may restrict data in the technical area | A config flag `competition.live_data_allowed`; when false, app runs in post-match/half-time mode only |
| Health data (GDPR Art. 9; Swiss revised FADP) | Injury risk about an identifiable player is health data | Role-based views; pseudonymised IDs in the analytics store; retention setting; export of individual scores disabled by default; access log |
| Medical-device rules (EU MDR Rule 11; Swiss equivalent) | Status depends on intended purpose and claims; decision-informing medical software starts at class IIa | Product wording controlled centrally (`app/wording.py`); forbidden phrases test (docs/06_UI_SPEC.md §6); intended-purpose statement in README |
| EU AI Act | Worker monitoring/evaluation is high-risk (Annex III) from 2 Dec 2027 for EU deployers | Human oversight built in (staff decide), logging of inputs/outputs/decisions, documentation of model and data (model card generated by M10) |

## Governance features the software must provide

- **Advisory only:** no automatic action; every alert requires a human acknowledgement, logged.
- **Decision log:** for each alert: time, level, reason, who saw it, action taken (none / physio
  check / discussed / substituted), free-text note.
- **Model card:** generated from the evaluation run (data, metrics, calibration, limits).
- **Player transparency:** a per-player report (post-match) explaining his values and reasons.
- **No misuse:** no screen designed for broadcast; no export to contract or scouting systems.
